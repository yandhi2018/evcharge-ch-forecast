# evcharge-ch-forecast

Прогнозно-аналитическая система общедоступной зарядной инфраструктуры электромобилей Швейцарии.

Проект по дисциплине «Прогнозно-аналитические системы» (РТУ МИРЭА, ИИТ, каф. ПМ, гр. ИНБО-20-23).

## Цель

Автоматизированный сбор, хранение, обработка и контроль качества данных об общедоступной зарядной
инфраструктуре электромобилей Швейцарии, построение прогнозов загрузки зарядных точек с учётом
погодных факторов и представление результатов анализа в виде интерактивных дашбордов.

Прогнозируемый показатель — почасовая доля занятых зарядных точек (коэффициент загрузки) в разрезе
кантонов и классов мощности, на горизонте от 1 до 24 часов вперёд.

## Источники данных

| Источник | Формат | Обновление | Роль |
|---|---|---|---|
| `ich-tanke-strom.ch` EVSEStatus | иерархический JSON (OICP) по HTTPS | каждые 15 мин | статусы точек (Available/Occupied/OutOfService/Unknown) |
| `ich-tanke-strom.ch` EVSEData | иерархический JSON (OICP) по HTTPS | по мере изменений, проверка раз в сутки | справочник точек (координаты, оператор, мощность, разъёмы) |
| Open-Meteo Historical Weather API | REST, колоночный JSON | почасово, с задержкой публикации | погода по кантонам |

## Архитектура хранения

Слоистая схема в PostgreSQL: `raw` → `staging` → `core` → `mart` → `ops`, плюс файловая зона
неизменяемых сырых копий ответов источников (для повторной обработки и прослеживания происхождения
данных). Подробности — в [`db/schemas`](db/schemas).

## Технологический стек

- Python 3.12 (`requests`, `SQLAlchemy`) — конвейер загрузки и прогнозные модели
- PostgreSQL 16 — хранилище данных
- Docker Compose — воспроизводимое развёртывание
- pytest + GitHub Actions — автоматическое тестирование

На последующих этапах: dbt-core, Metabase, scikit-learn, LightGBM.

## Структура репозитория

```
config/            конфигурация источников, интервалов загрузки, опорных точек погоды
src/ingestion/      модули загрузки трёх источников
db/schemas/         описание слоёв хранения (raw/staging/core/mart/ops)
tests/              автоматические тесты (инкрементальность, идемпотентность, устойчивость к сбоям)
.github/workflows/  CI (pytest при каждом изменении)
```

## Запуск

`config/config.yaml` уже содержит рабочие адреса источников и 26 опорных точек погоды —
менять его нужно только при смене источников. Секреты — только в `.env` (не коммитится).

```bash
cp .env.example .env      # заполнить реальным паролем БД
psql -U evcharge -d evcharge -f db/schemas/ddl.sql   # один раз — создать схемы и таблицы
pip install -r requirements.txt

python -m src.ingestion.evse_status   # разовый запуск сборщика статусов
python -m src.ingestion.evse_data     # разовый запуск сборщика справочника точек
python -m src.ingestion.weather       # разовый запуск сборщика погоды
```

Непрерывный сбор статусов (раз в 15 минут) и справочника/погоды (раз в сутки) настроен через
Планировщик заданий Windows — см. `scripts/register_scheduled_tasks.ps1`.
